## 経緯

2026-07-20〜21 に、使用量の残りを見ながら自律的にタスクを回すループ（autoloop v1）を作った。
ユーザーの意向で**すべてロールバック済み**（ファイル・systemd timer・statusline の変更・PR #36 をすべて撤去）。
ゼロから設計し直す予定なので、保留として残す。

## やり直すときの要件（ユーザー）

v1 のようにバックグラウンドに常駐する形だと、結果に気づきにくい。

1. 明示的にコマンドを打ったときだけ動く（セッション内・オンデマンド起動）
2. 結果が確実に目に入る
3. cron / systemd などローカル環境への永続的な変更は極力避ける。入れる場合は必ず明示し、提案 → 合意 → 導入の順にする（timer・フック・statusline の改変も同じ）

## 技術知見（v1 で検証済み）

- 5時間枠・週枠の残量 % をプログラムで取れる公式の手段は、statusline JSON の
  `rate_limits.five_hour` / `seven_day`（used_percentage、resets_at）だけ。Pro / Max のみで、
  対話セッション中しか更新されない。`claude usage` CLI は存在せず、OTel にも残量のメトリクスは無い
- ネイティブの /loop・CronCreate はセッションが終わると止まる。繰り返しタスクは7日で失効する
- `claude -p` の結果 JSON を jq で判定するとき、`//` は false を欠損扱いする（`.is_error // true` はバグになる）
